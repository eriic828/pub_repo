搜索1 → 等待结果 → 搜索2 → 等待结果 → 搜索3 → ...

## 🔴 问题2：WebSearch无返回时仍输出内容

### 问题描述
- WebSearch返回占位符文本，没有真实结果
- 仍然继续生成选题报告
- 编造了来源链接和评分内容

### 根本原因
1. 没有检查WebSearch结果的有效性
2. 没有在搜索失败时停止执行
3. 违反了"基于真实搜索结果"的核心原则

### 修复方案

#### 修改1：第二步搜索前增加有效性检查

**修改位置**: "【第二步】基于热搜词执行搜索"

**新增约束**:
```markdown
> ⚠️ 关键约束：执行搜索前必须检查WebSearch结果是否包含真实内容！

检查规则：
- 如果返回占位符文本 → 判定为失败
- 如果返回空列表 → 判定为失败
- 只有返回具体的标题、链接、摘要 → 才判定为成功

失败处理：
1. 轨道B全部失败 → 仅使用GitHub Trending的热点词
2. 第二步搜索结果不足 → 扩大搜索范围
3. 候选内容 < 10条 → 停止执行，禁止编造
```

**新增输出要求**:
```markdown
【搜索结果统计】

搜索1: [有效结果数量] 条
搜索2: [有效结果数量] 条
...
搜索10: [有效结果数量] 条

总有效结果：[总数] 条
```

#### 修改2：强化搜索结果不足处理

**修改位置**: "采集目标与处理"

**新增规则**:
- 候选内容 < 20条 → 输出警告⚠️
- 候选内容 < 10条 → 停止执行，提示用户
- **绝对禁止**编造选题、标题、链接
- **绝对禁止**输出无真实来源的选题
