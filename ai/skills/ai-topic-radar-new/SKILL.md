### Phase 2: 串行搜索（⚠️ 必须串行，禁止并行）

```
搜索流程（串行）：

```

**❌ 禁止**：同时发起多个搜索请求
**✅ 正确**：一次只发起一个搜索，等待结果后再发起下一个

- 累计 ≥ 50条 → 正常输出
- 累计 30-49条 → 输出警告⚠️，继续输出
- 累计 < 30条 → 输出警告⚠️，提示用户"搜索结果有限"

### Phase 3: 智能评分 & 排序

📖 **详细评分规则**: 参考 [references/scoring-criteria.md](references/scoring-criteria.md)

**评分公式**：
```
综合评分 = 人设匹配度 × 0.4 + 爆款潜力 × 0.6 + 时效性加分
满分 = 120分
```

**时效性加分（精细化）**：
- 近7天内容: +20分
- 近14天内容: +15分
- 近30天内容: +10分
- 31-60天内容: +5分
- 61-90天内容: +2分
- 更早内容: 0分

**星级标准**：
- ⭐⭐⭐ (100+分): 强烈推荐
- ⭐⭐ (85-99分): 值得创作
- ⭐ (70-84分): 备选

**过滤规则**：
- 去除纯新闻（无实操指导）
- 去除重复选题（标题相似度>70%）
- 保留综合评分 > 70分的内容

## 🚨 强制规则（违反将导致执行失败）

### 核心强制规则

1. **🔴 完整展示热点词聚合过程**：必须展示每个来源的完整原始列表，禁止省略
2. **🔴 串行搜索**：搜索必须串行执行，一次只发起一个搜索请求
3. **🔴 有效结果≥50条**：必须持续搜索直到累计有效结果≥50条
4. **🔴 API Key 强提醒**：Tavily 未配置时，必须强提醒用户配置
5. **禁止编造内容**：所有选题必须有真实原文链接

### 常规规则

6. 永远不要输出少于10个选题（除非搜索结果确实不足）
7. 必须包含 Sources 部分
8. 每条选题必须包含原文链接行
9. 优先展示100分以上的爆款级选题
10. 避免重复：同一主题只保留评分最高的版本
11. 时效优先：相同评分时，优先推荐最新内容
12. 爆款优先：技术深度不是唯一标准，传播潜力更重要
13. 可读性保证：避免推荐过于专业、门槛过高的技术文
14. 标题建议必须具体：每个选题提供3个公式的具体标题示例
15. 公众号优先：搜索结果中应优先包含微信公众号爆款文章
16. 动态日期替换：搜索中的日期占位符必须替换为当前日期
17. 搜索聚焦热点词：所有搜索必须围绕{HotKeyword}或{UserKeyword}
